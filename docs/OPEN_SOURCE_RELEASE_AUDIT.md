```text

.github/workflows/    CI with contents: read
```

Uploads become RawSource records, parsed text, ClaimCards, EvidenceSpans and source
profiles. Scope-aware retrieval feeds Q&A, briefing and committee workflows. The
committee selects predefined analytical seats and runs discussion/synthesis with
evidence and quality gates. Chat history, decisions, outcomes and traces are
persisted for later inspection/replay. SQLite is the local default; PostgreSQL/
pgvector is optional. OpenRouter supplies role-specific models; OCR/embedding and
optional external data services have separate configuration. Redis/Celery/MinIO
support deployment workflows.

The code does not establish that arbitrary authors can already be faithfully
reconstructed as independent Minds. That remains a product direction; it is not
marketed as an achieved capability or a proven committee quality improvement.

## 6. Security Audit

### Secrets

Scanned Git-tracked working files, the reviewed publication inventory and every
reachable historical blob. Gitleaks checked token patterns and entropy. Additional
checks covered cloud/vendor keys, JWTs, private-key headers, URL credentials,
cookies/Bearer candidates, encoded literals, phones/identity numbers, MACs and
personal paths. No confirmed live credential was found. Historical Gitleaks
findings: 16 manifest SHA-256 values and five template/workflow-label matches.
Test keys are explicit synthetic strings; example DSNs use loopback/container
hosts and example passwords. No real key was printed or persisted by the audit.

### PII

No private email, phone, ID, home path or device identity was confirmed. A phone
pattern candidate was a synthetic financial magnitude. PDF compressed bytes gave
email-like regex matches; the complete files reproduce from synthetic content.
The author/committer uses the expected public GitHub noreply identity. Public
upstream attribution/license contacts are not private project identity leaks.

### Commercial data

Reviewed source/docs/fixture inventories and URL hosts. No customer records,
contracts, quotations, private company domains, internal production endpoints or
real business documents were identified. Public market-data/provider endpoints,
technical specifications and deliberately synthetic examples remain. Local test
databases, uploads, logs and audit reports are ignored and excluded from the manifest.

### Git history

After read-only fetch, there are three reachable commits, local main/audit branch,
origin/main and no tags. Authors/messages/stats/names/objects were inspected.
No inherited private history, secret file, database, upload archive or deleted
private corpus was found. Initial source import plus two small public-preparation
fixes is consistent with the clean-source strategy. Old brand words in commit
messages are harmless history and are intentionally not rewritten.

### Config

Local starter binds loopback and forwards declared backend settings, not arbitrary
application secrets. `.env` variants, keys, databases, caches, runtime data, backups
and local corpora are ignored; `.example` templates remain allowed. Production
rejects empty API credentials, dev secrets, template secrets and unsafe profiles.
Documentation warns about external model transmission, single-user boundaries,
document rights and development credentials. Uploaded content is untrusted input.

### GitHub Actions

`contents: read`; no write-all, pull_request_target, raw secret/environment dump or
untrusted PR title/body interpolation found. PR code does not receive project
secrets. Uploaded frontend evidence is a scoped generated JSON report. Cache,
official action usage and container builds were inspected. Action version/runtime
maintenance remains P2. Remote runs on this changed tree were not initiated.

### Docker

Both final Dockerfiles build; backend runs as appuser. Development ports bind
loopback; production templates use required placeholders and internal service
connections, with explicit runtime production guards. No real domain/server IP,
password, DSN or key is baked into sources. Frontend build explicitly includes
build-time devDependencies. Independent container health and production-rejection
checks pass. TLS, secrets provisioning and complete production isolation remain
deployment responsibilities; they were not configured on a real server.
